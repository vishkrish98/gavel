Read CONTEXT.md first. Do Step 4 only: the agent team, using the HW5 backend/agents.py pattern (PydanticAI, one shared gpt-6-luna model via OpenAIResponsesModel, reasoning effort low, typed outputs, prompts as markdown files in backend/prompts/).

1. POLICY COMPILER: reads the policy paragraphs and returns, for each paragraph that states a binding rule, a rule object (type from the list in CONTEXT.md, parameters, paragraph id, exact quote). Guidance ("may consider") and info paragraphs are not rules. Rules are saved with propose_rule (quote verified in code) and then approved by a human click; for the benchmark run, a flag auto-approves rules that verified AND match nothing else, and the audit trail records auto_approved_for_benchmark.
2. REQUEST READER: for each line, returns category (food, alcohol, gift_card, prize, speaker_fee, lodging, apparel, equipment, printing, supplies, venue, registration), headcount, quantity, nights and unit cost, using only the line description and amount. Ambiguous wording ("refreshments incl. craft beer") must be classified by substance. Runs requests in parallel (asyncio, semaphore of 8).
3. SKEPTIC: for each line the Reader put in a permissive category, tries to find a reason the true category is more restrictive or a fact is wrong. It may flag a line for human review with a reason; it never changes a category on its own. The Engine applies verdicts in code.
4. ENGINE and OPTIMIZER: not LLM agents. Wrappers over run_engine and allocate.
5. DRAFTER: from the verdicts, drafts (a) per-request committee questions (for needs_docs and flagged lines, and for requests with large reductions), citing the rule and quote; and (b) a decision memo for the whole pot. Stored as awaiting_approval; nothing is exported until a committee approval click. Drafts contain no judgment of any club's character.
6. CHAIR (Boss): orchestrates one run: compile rules (once), read requests in parallel, Skeptic, engine, consistency report, optimizer, drafter. It records run status.
7. Limits on every agent run: wall-clock timeout, request_limit, per-agent token cap, whole-run token cap of 400,000. Hitting a limit ends the run cleanly with a recorded reason.
8. Command: python -m backend.run_check. It runs the full pipeline and scores against the keys: rule recall and precision, quote validity, decoy paragraphs wrongly turned into rules (expect 0), category accuracy per category, verdict accuracy on all 158 lines (overall and per verdict type), allowed-dollar accuracy, number of lines flagged by the Skeptic and how many were actual errors, and consistency-report agreement.
9. Save one complete run as output/trace_run1.json: every agent step, tool call, tool result, verdict and discard, in order.
